Domain terms across paper notation, blockchain, cryptography, and Vietnamese agriculture. Maintained so reviewers, contributors, and the codebase use the same vocabulary.

## Paper notation (locked — must match `frontiers.tex` lines 1346–1409)

| Symbol                              | Code name                                    | Meaning                                                                                         |
| ----------------------------------- | -------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| $\phi$                              | `phi` (TS) / `bytes32 phi` (Solidity)        | Unique project identifier                                                                       |
| $p_i$                               | `productIndex` (rare)                        | i-th product unit in project $\phi$                                                             |
| $N$                                 | `n` / `batchSize`                            | Number of products in a batch (≤ 500)                                                           |
| $sid_i$                             | `sid` (TS) / `bytes calldata sid` (Solidity) | Secret identifier for product $p_i$, ∈ {0,1}^k. Generated by CSPRNG. Encoded in the private QR. |
| $\mathsf{Gen}(k)$                   | `generateSid(byteLength)`                    | CSPRNG returning $sid \in \{0,1\}^k$                                                            |
| $h_i$                               | `h` / `hash`                                 | $\mathsf{H}(sid_i)$ — bytes32, on-chain product reference                                       |
| $\mathrm{H}(\cdot)$                 | `sha256(...)`                                | Cryptographic hash function (SHA-256)                                                           |
| $status_i$                          | `redeemed` (bool)                            | Redemption state ∈ {`unused`, `redeemed`}                                                       |
| $\mathcal{R}$                       | `registry` (conceptual)                      | On-chain registry: `mapping(phi → addr_P)` + `mapping((phi, h_i) → status_i)`                   |
| $\mathcal{R}[\phi]$                 | `projects[phi].producerAddress`              | Registered producer for project $\phi$                                                          |
| $\mathcal{R}[\phi, h_i]$            | `products[phi][h]`                           | On-chain state of product $p_i$                                                                 |
| $\mathsf{SC}$                       | `ProductRegistry.sol`                        | The smart contract                                                                              |
| $\mathrm{addr}_{\mathcal{P}}$       | `producerAddress` / `addr_P`                 | Blockchain address of producer $\mathcal{P}$                                                    |
| $\mathcal{P}$                       | (role: Producer)                             | Authorized manufacturer (HTX rau)                                                               |
| $\mathcal{C}$                       | (role: Consumer)                             | End user verifying a product                                                                    |
| $\mathcal{I}$                       | (role: Coordination Hub)                     | Intermediary submitting transactions on behalf of consumers                                     |
| $\mathcal{A}$                       | (modeled, not runtime)                       | Probabilistic polynomial-time adversary                                                         |
| `AUTHENTIC`                         | `VerificationOutcome.AUTHENTIC`              | First successful verification of a valid, unredeemed product                                    |
| `ALREADY_VERIFIED`                  | `VerificationOutcome.ALREADY_VERIFIED`       | sid was previously redeemed                                                                     |
| `COUNTERFEIT`                       | `VerificationOutcome.COUNTERFEIT`            | sid not in registry                                                                             |
| $\mathrm{QR}^{\mathrm{pub}}_{\phi}$ | `publicQR`                                   | Public QR for project $\phi$ (URL → metadata page)                                              |
| $\mathrm{QR}^{\mathrm{priv}}_{p_i}$ | `privateQR`                                  | Private QR for product $p_i$ (URL contains $sid_i$)                                             |
| $tx$                                | `txHash` / `txid`                            | Blockchain transaction hash                                                                     |
| `CID`                               | `ipfsCid`                                    | IPFS Content Identifier of pinned dApp build                                                    |

### Security requirements (paper §3.4)

| Symbol                       | Meaning                                                                                                                                                  |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **SR1 — Unforgeability**     | No PPT adversary can produce a valid identifier for a `phi` that the registry does not contain.                                                          |
| **SR2 — Non-replayability**  | At most one verification of a given $p_i$ can return `AUTHENTIC`; subsequent calls return `ALREADY_VERIFIED`.                                            |
| **SR3 — Non-repudiation**    | Every state change `unredeemed → redeemed` produces an immutable, timestamped, publicly auditable record.                                                |
| **SR4 — Trust independence** | Verification correctness does not depend on $\mathcal{I}$'s honesty. Even if compromised, $\mathcal{I}$ cannot fabricate or alter verification outcomes. |

### Practical requirements (paper §3.5)

| Symbol                                      | Meaning                                                                           |
| ------------------------------------------- | --------------------------------------------------------------------------------- |
| **R1 — Cost-effectiveness & Deployability** | Use widely-available low-cost components; integrate without specialized hardware. |
| **R2 — Performance & Scalability**          | Support high volumes with low latency; efficient batch registration.              |
| **R3 — User-oriented Accessibility**        | Verification via standard QR scan, no specialized devices/apps/expertise.         |

## Blockchain & cryptography

| Term                               | Definition                                                                                         |
| ---------------------------------- | -------------------------------------------------------------------------------------------------- |
| **Polygon**                        | Public EVM-compatible blockchain. Used as the immutable registry layer.                            |
| **Polygon Amoy**                   | Polygon's testnet (replaced Mumbai in 2024). Free MATIC from faucet. Default network in this repo. |
| **Polygon mainnet**                | Production network. Real MATIC required. Repo supports but does not deploy by default.             |
| **EVM**                            | Ethereum Virtual Machine — the runtime Polygon implements.                                         |
| **Smart contract**                 | Self-executing program deployed on a blockchain.                                                   |
| **Wallet**                         | Public/private keypair authorized to sign transactions.                                            |
| **EOA**                            | Externally Owned Account (vs Contract Account).                                                    |
| **Gas**                            | Computational cost of EVM execution; paid in native token (MATIC on Polygon).                      |
| **Tx / Transaction**               | Signed message changing on-chain state.                                                            |
| **Event / Log**                    | Emitted record from a contract, indexed for off-chain query.                                       |
| **ABI**                            | Application Binary Interface — JSON description of contract functions/events.                      |
| **NatSpec**                        | Solidity native documentation format (`/// @notice ...`).                                          |
| **`view` function**                | Read-only contract function that doesn't modify state; free to call.                               |
| **Slither**                        | Static analysis tool for Solidity.                                                                 |
| **Mythril**                        | Symbolic execution tool for Solidity (deferred to v2).                                             |
| **Foundry**                        | Solidity testing framework (`forge`, `cast`, `anvil`).                                             |
| **Hardhat**                        | JS-based Solidity testing/deployment framework.                                                    |
| **Property test / Invariant test** | Test asserting "for any input X, property P holds" (vs example-based unit test).                   |
| **Fuzz test**                      | Property test driven by random inputs.                                                             |
| **CSPRNG**                         | Cryptographically Secure Pseudo-Random Number Generator.                                           |
| **SHA-256**                        | Cryptographic hash function used by this paper for `h_i = H(sid_i)`.                               |
| **`keccak256`**                    | EVM's default hash; NOT used here (paper specifies SHA-256).                                       |
| **Preimage resistance**            | Property of a hash function: given $h$, cannot find $x$ such that $H(x) = h$.                      |
| **PPT adversary**                  | Probabilistic Polynomial-Time attacker (standard cryptographic threat model).                      |

## IPFS

| Term          | Definition                                                           |
| ------------- | -------------------------------------------------------------------- |
| **IPFS**      | InterPlanetary File System — content-addressed distributed storage.  |
| **CID**       | Content Identifier — IPFS hash of file content.                      |
| **Pinning**   | Persistently storing data on an IPFS node so it remains retrievable. |
| **Pinata**    | Commercial IPFS pinning service used in paper §8 + this repo.        |
| **`ipfs.io`** | Public HTTP gateway: `https://ipfs.io/ipfs/<CID>/...`.               |
| **Kubo**      | Reference Go implementation of IPFS daemon.                          |
